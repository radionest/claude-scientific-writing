## Волна 1 — корректность гейта

### PR-1 (#14): doc-abbrev-* выдают находку на каждом вхождении

`lib/checks/consistency.py:30-48` (`doc-abbrev-variants`) даёт один Hit по редчайшему
варианту, `:51-77` (`doc-abbrev-first-use`) — один Hit на точке раскрытия. Хук и
`/text-review` по умолчанию в `--diff`: якорь обычно на старой нетронутой строке, новый
вариант в изменённой строке теряется. Прецедент — `doc-token-case` (`:89-129`, d068b2e).

1. `abbrev_variants`: доминирующий вариант — самый частый (ничья → сообщаются все, по
   образцу `token_case`); yield на **каждом** вхождении каждого недоминирующего варианта.
2. `abbrev_first_use`: yield на каждом «голом» употреблении до раскрытия (в т.ч. на новом)
   и на самом раскрытии.
3. `tests/test_checks.py`: два употребления аббревиатуры на разных строках → находки на
   обеих; прогнать через `lint_file(..., changed={новая_строка})` — finding выживает.
   Проверить, что существующие тесты не утверждали ровно одну находку.

## Волна 2 — контракт локального словаря

### PR-3 (#8, #9): exit-код конфиг-ошибки 2 → 3

`argparse` уже выходит с 2 на любую ошибку CLI — хук примет её за «битой словарь»
(hooks/text-lint.sh:41-44). Решение: конфиг-ошибке — код 3 (свободное значение).

1. `lib/lint_prose.py:364` — `return 2` → `return 3` (ветка `ConfigError`).
2. `hooks/text-lint.sh:41` — `rc -eq 2` → `rc -eq 3`; собственный exit хука остаётся 2 в
   обеих ветках, поэтому `tests/test_hook.py:38,75` не меняются.
3. `tests/test_local_dict.py:242,250` — `rc == 2` → `rc == 3`.
4. `docs/design.md:186` — строка Exit-контракта: `2` → `3`.
5. (#9) `commands/text-review.md:26-27` — в note добавить: локальный словарь
   `<git-root>/.claude/scientific-writing/dictionary.json` автоподхватывается; exit 3 =
   словарь битый (stderr называет файл и ошибку).
6. Тест на коллизию: `python3 -m lib.lint_prose --bogus x.qmd` → exit 2 (argparse),
   битый словарь → exit 3 — оба различимы.

### PR-4 (#10, #11): схема и видимость оверлея

**#10 — валидация `layer`.** `load_raw` (lib/lint_prose.py:64-139) не читает `layer`,
хотя все доки описывают его как часть схемы; enum уже утверждён тестом базового словаря
(tests/test_dictionary.py:17): `universal | genre:report|article|educational | doc`.

1. В `load_raw`: если `layer` присутствует — проверять enum; для **новых** (не
   override-by-id) записей — требовать presence (включить в `required`, как
   `severity`/`message`; partial-override наследует `layer` базы, строки 100-101).
2. `tests/test_local_dict.py`: `layer: "wrong"` → `ConfigError`; отсутствие `layer` у
   **новой** записи → `ConfigError` (у override-by-id наследуется от базы). Значение
   `layer: "universal"` в оверлее законно — enum разрешает все; требовать именно
   `layer: doc` не нужно.

**#11 — оверлей в linked worktrees.** `_git_root` (lib/lint_prose.py:271-282) берёт
`--show-toplevel` = корень **worktree**, а не main checkout; если проект gitignore'ит
`.claude/`, оверлей есть только в main checkout и worktree его молча теряет.

1. `local_dict_path`: корень worktree (как сейчас) → если оверлея нет, второй кандидат —
   корень main checkout из `git rev-parse --path-format=absolute --git-common-dir`
   (срезать хвост `/.git`; для не-worktree общий dir == `.git` внутри toplevel — кандидат
   совпадает с первым, деградации нет). Порядок: own-worktree копия ветки важнее main.
2. `tests/test_local_dict.py`: репозиторий + `git worktree add` (tmp_path), оверлей
   только в main и в `.gitignore` → линтер из worktree видит правила; tracked-оверлей →
   worktree видит свой.

### PR-10 (#22): pandoc-путь теряет комментарии на заголовках

1. `extract_comments` (:128-137): `COMMENT_RE` по **всем строкам** pandoc-markdown, не
   только `section.paragraphs` — комментарий на заголовке живёт в строке заголовка.

## Волна 5 — канон и документация

### PR-8 (#16): `_STOP_REPEAT` → настраиваемый `allow`

`lib/checks/consistency.py:20-23` хардкодит 15 слов, замыкая их в allow (:143) — оверлей
может только добавить. Докстринг самого правила говорит, что порог частоты делает
стоп-лист лишним, но это верно не для коротких текстов: «очаг» ≤6 раз в документе порогом
не накрывается. Поэтому — не удалять, а сделать настраиваемым.

1. `canon/orthography.json`, запись `doc-repeat-window` (:11): `allow` ← те 15 слов
   (строчными, как сейчас во frozenset; формы покрывают оба пути — surface и lemma-ключ).
2. `consistency.py`: удалить `_STOP_REPEAT` (:20-23) и `| _STOP_REPEAT` (:143).
3. Семантика оверлея: project `allow` **заменяет** canon-allow (field-wise override) —
   кто хочет добавить, перечисляет свой список; отметить в note записи.
4. `tests/test_checks.py`: поведение повтора без изменений; оверлей со своим `allow`
   заменяет canon-список.

### PR-9 (#17): скиллы ↔ canon

`CLAUDE.md:22` + `AGENTS.md:22` + `docs/design.md:133` утверждают, что прозо-скиллы
**ссылаются** на `canon/`; в `skills/writing-russian-academic-prose/SKILL.md` и
`skills/say-it-once-academic-prose/SKILL.md` нет ни одного упоминания canon/ — два
источника молча расходятся.

Решение (рекомендую консолидацию): в обоих скиллах заменить инлайн-таблицы кальки на
указатель «машиночитаемый источник — `${CLAUDE_PLUGIN_ROOT}/canon/dictionary.json` +
`canon/orthography.json`; поле `skill` маршрутизирует находку к этому скиллу; при
расхождении канон прав», оставив в скиллах только сужденческую прозу (когда тире
законно, ритм и т.п.). Альтернатива, если скиллы обязаны быть самодостаточными без чтения
файлов: смягчить формулировку в трёх доках («словарь посеян из таблиц скиллов; канон
линтера авторитетен»). Изменить все три документа согласованно; проверить, что
`hermes/skills/scientific-writing/SKILL.md` не дублирует претензию.
