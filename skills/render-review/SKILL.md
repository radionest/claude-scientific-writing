Ревью дефектов, материализующихся только в рендере (текст таблиц, подписи). Совещательно.

`CLAUDE_PLUGIN_ROOT` — корень установленного плагина. Если переменная не задана (zcode), возьми корень из пути этого SKILL.md: он лежит на два уровня ниже корня плагина (`<корень>/skills/<имя>/SKILL.md`). Для pytest используй `.venv` в корне плагина; если её нет — скажи явно, что прогон pytest недоступен.

## Шаги
1. Определи `render.docx` (`$R`) и исходный `source.qmd` (`$Q`) из аргументов вызова. Без них — спроси.
2. Линт рендера:
   `PYTHONPATH=${CLAUDE_PLUGIN_ROOT} python3 -m lib.render_lint "$R" --qmd "$Q" --json`.
   Находки: `unit` — якорь в docx (`tbl2 r1 c3` / порядковый номер абзаца), `qmd` — строка
   исходника (генерирующий чанк). Прочитай `severity`: error/warn/info.

Exit-коды линтера (`lib.render_lint`):

| Exit | Значение |
|---|---|
| 0 | чисто или только warn/info находки |
| 1 | error-находки (совещательный сигнал) |
| 2 | вход не читается — .docx повреждён, не zip, OLE-контейнер или пароль; файл или `--qmd` не найден |
| 3 | конфиг: битый оверлей проекта или исходник `--qmd` не в UTF-8 |

Ошибка аргументов argparse тоже выходит с кодом 2 (usage в stderr).

3. Параллельно (в ОДНОМ сообщении) субагент `prose-reviewer` с измерением `render`: передай
   путь к `source.qmd`, `<doc>.spec.md` вместе с её разделом «Зафиксированные решения»
   (процитируй раздел в задаче; раздела нет — передай spec без цитаты; политика
   закрытия — в «Статусах находок» агента `prose-reviewer`), жанровый профиль
   (`canon/profiles/<жанр>.md`).
4. Синтез: дедуп по (док-якорь, проблема), ранжир blocker → warning → nit, единый отчёт.
   Замечание, противоречащее разделу spec «Зафиксированные решения», пометь
   `declined-by-owner-decision` со ссылкой на решение — в стадию fix оно не идёт
   и в следующих раундах заново не поднимается; сомнительное покрытие — вопрос владельцу
   в отчёте, не находка на правку.
   Находку линтера с `qmd`-хинтом указывай парой: якорь в рендере + строка чанка-источника.
5. Правки — в стадии fix скилла `scientific-writing:writing-scientific-documents`: меняется
   генерирующий чанк (условная эмиссия строк и т.п.), не рендер; перегони render_lint до чистого.
